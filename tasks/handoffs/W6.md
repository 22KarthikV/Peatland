**RunStatus:** polls `GET /runs/{id}` with exponential backoff (`pollConfig`: 2 s start, x1.5, cap 15 s; mutable for tests), stops on succeeded/failed/cancelled, on a non-network API error (404 etc.; "Try again" button), or after 3 consecutive network failures. Aborts the request and clears the timer on unmount. Shows status and `step: done of total` in an `aria-live="polite"` region plus a labelled `<progress>`, timestamps, `ApiErrorMessage` for `run.error`, and for failed/cancelled a Retry button that POSTs `run.params` unchanged to `/sites/{site_id}/runs` and navigates to the new run (errors shown inline). Success links to the site map (and the change view when `outputs.change_id` is set). The page is keyed on the run id so navigating to the new run resets state.
**New run entry:** form on the site map page (start date, end date, one window, `max_cloud_cover_pct` 60 sent explicitly because the generated type marks it required; default model). It posts to `/sites/{id}/runs` and navigates to `/runs/{id}`. No model or multi-window choice.
