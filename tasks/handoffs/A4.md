# A4 handoff: API key and rate limit

Done. `security.py` was split (git mv) into:
- `api/src/api/auth.py`: `hash_key`, constant-time `is_valid_key` (loops all hashes, no early exit), `load_secret_hashes`/`load_key_hashes`, `SettingsDep`, `require_api_key` (401 in `{code,message,detail}`).
- `api/src/api/ratelimit.py`: `RateLimiter`, `JOB_ROUTES`, `enforce_rate_limit` (429 with `Retry-After`, `RateLimit-*` headers; 10/min job routes, 120/min others, unchanged).
- `main.py` computes `app.state.api_key_hashes` once at startup (env `API_KEYS` hashes plus Secrets Manager).

Key sources:
- `API_KEYS`: comma-separated SHA-256 hex digests (as before).
- `API_KEY_SECRET_ID` (new setting `api_key_secret_id`, default empty = disabled), e.g. `peatwatch/api-key`. Secret value = comma-separated plaintext keys (dev: `dev-only-key` from infra/localstack/init.sh) or 64-hex digests; plaintext is hashed on load and not retained. boto3 uses `AWS_ENDPOINT_URL` / `AWS_REGION`. On any failure it logs a warning and falls back to env hashes only.
- Compose/env: set `API_KEY_SECRET_ID=peatwatch/api-key` for the api service to use LocalStack (not touched by me).

Tests: `api/tests/test_auth.py` (boto3 mocked; LocalStack test gated by `localstack` marker plus `RUN_LOCALSTACK=1`). Existing tests' imports updated. No new deps (boto3 already in api/pyproject.toml).
