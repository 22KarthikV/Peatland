**Decisions / gotchas:**
- Client validation (`components/boundary.ts`): valid JSON; Polygon, MultiPolygon or Feature wrapping one (FeatureCollection rejected); rings of 4+ finite positions, closed, lon/lat in range; every vertex inside the A3 envelope (EPSG:32630 (295100, 5995100)-(504900, 6204900), via a local lon/lat to UTM 30N conversion); spherical area estimate (holes subtracted) at most 50,000 ha. Server stays authoritative. The Feature wrapper is stripped and only the geometry is sent. Slug is not exposed (server derives it).
- Preview is a plain SVG outline plus a text summary (polygon count, estimated ha); no map library was added. W3 owns the real map.
- Errors use `{code,message,detail}`: `ApiErrorMessage` shows message, code and flat `detail` entries in `role="alert"`; a thrown fetch error becomes a client-side `internal_error` message.
- Accessibility: labelled inputs, `aria-invalid`/`aria-describedby`, alerts and status regions, focus moves to the file input if submitting without a valid file.
- **Test gotcha (W1 client):** `api` in `src/api/client.ts` is created at import, and openapi-fetch captures global `fetch` at that moment, before MSW patches fetch in `beforeAll`, so tests using the shared `api` hit the real network ("fetch failed"). `sites.test.tsx` works around it by mocking `../api/client` with a per-call client. W3+ tests need the same, or client.ts could pass `fetch: (r) => globalThis.fetch(r)` to `createClient` (out of my file scope; suggested for W1 owner).
