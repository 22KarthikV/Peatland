**Decisions / gotchas:**
- **Leakage:** patches of all sources are split in one `split_bounds` call (same defaults as the baselines: 5 km blocks, 1 km buffer, 60/20/20, split seed 0, Glen Trool hold-out). Training reads only `train` patches, validation only `val`; `test` patches are never opened. The normaliser and class weights come from train patches only (tested). Two sources over the same area (e.g. two years) put the same location in the same split. `split.json` in the output dir records per-patch splits, block assignments and the train/val items for the M10 leakage re-check. `last.pt` stores a digest of the train/val items, and resuming with a different split raises.
- **Preprocessing contract:** standardise with the train-fitted `BandNormalizer`, then NaN becomes 0. `UNetPredictor` applies it to raw windows, so evaluate it with a `PatchDataset(normalize=None, nan_policy="keep")` (same as the RF baseline). Invalid pixels (any band NaN) are ignored in the loss and become 255 at inference.
- **Class weights `auto`:** `total / (K_present * count)` over labelled valid train pixels, capped at `class_weight_max` (50); 0 for classes absent from train.
- **Determinism and resume:** shuffle and augmentation generators come from `(seed, epoch[, index])`. The LR is a stateless cosine of `(epoch, epochs)`, with no scheduler state. The resume test checks that 1 epoch plus a resume to 3 matches 3 epochs straight (weights within 1e-5). Raising `train.epochs` and rerunning extends a finished run. `last.pt` and `best.pt` are written atomically.
- **MLflow:** the file store raises in MLflow 3.17 (maintenance mode), so the default is `sqlite:///<output.dir>/mlflow.db` with artifacts in `<output.dir>/mlartifacts`. The run id is saved in `last.pt` and reused on resume. Params are the flattened config plus split counts, class counts and weights. Metrics per epoch: `train_loss`, `lr`, `val_loss`, `val_miou`, `val_iou_{0..3}`, `best_score`. Artifacts: `split.json`, `config.json`. Weights are not logged as MLflow artifacts; they stay in the output dir.
- **Best model:** chosen by val mean IoU, or by lowest train loss if there is no val split.
- **No `peatwatch-ml` CLI exists yet**, so there is no `peatwatch-ml train` entry point. The entry is `python -m ml.train --config ml/configs/unet.yaml [--out-dir D] [--epochs N] [--no-resume]`, as in SPEC. Hook `ml.train.main` in when the CLI is added (M10 references `peatwatch-ml evaluate`).
- The smp import uses `# type: ignore[import-untyped]` because smp ships no `py.typed`.
- Tests use `resnet18`, depth 3, 32 px patches, `encoder_weights=None`. Nothing is downloaded. Tests `importorskip` torch/smp, so they skip in an environment without the extra.

**How to run on Colab (M9):**
1. Colab has CUDA torch preinstalled. Do **not** `uv sync --extra train` there, because the lock pins CPU wheels. Use: `pip install -e ./pipeline -e ./ml && pip install "segmentation-models-pytorch>=0.5"` (with Colab's torch/torchvision), or `uv pip install` the same into Colab's env.
2. Put the composite(s) and label raster(s) on Drive. Edit a copy of `ml/configs/unet.yaml`: set `data.sources`, set `model.encoder_weights: imagenet` (downloads ResNet weights, and smp adapts conv1 to 18 bands), set `output.dir` to a Drive folder (for example `/content/drive/MyDrive/peatwatch/unet`), and set `train.num_workers: 2`.
3. `python -m ml.train --config <copy>.yaml`. If the session dies, rerun the same command: it resumes from `<output.dir>/last.pt`, with the same MLflow run.
4. Copy `best.pt` back to `artifacts/` and check it with `ml.model.load_predictor(path)` on CPU (no network needed, since weights come from the file).
