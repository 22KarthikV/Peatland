**How it works:**
- Loads site + classifications; dates sorted ascending; From/To preselect the two latest. From must be earlier than To (alert, compute disabled).
- Two comparison modes: swipe (two stacked MapViews, top one non-interactive and CSS `clip-path` clipped by a range slider) and side by side (two MapViews). Cameras are synchronised through shared state (`jumpTo` on the other map; only user-originated `move` events propagate, so no loops).
- "Compute change" POSTs `/sites/{id}/changes` with `{year, season}` of both windows. 200 gives the Change; 202 polls `GET /runs/{id}` (`pollConfig.ms`, 2000, mutable for tests) until `succeeded` then uses `outputs.change_id`. Then `GET /changes/{id}/stats`. failed/cancelled and API errors (e.g. 422 `classification_missing`) show as alerts. Changing a date cancels any in-flight poll.
- "Show change layer" (enabled once stats are ready) replaces the comparison with one MapView on `change.tile_url`; the download link uses `change.download_url`.
- Transitions list (buttons, `aria-pressed`) with a detail line: from class to to class, ha, % of site.
**Gotchas / not done:**
- Clicking a transition on the map is not implemented (list only): the contract does not say how change COG pixel values encode (from, to), so the point lookup could not be decoded. The change raster's colouring comes from TiTiler; the legend shows land classes only, not change codes.
- The swipe slider is a range input (keyboard accessible), not a draggable divider on the map.
- Only the first page (limit 50) of classifications is used. The change view uses the default model.
- W5 can reuse `ChangeStats` already fetched in `Change.tsx` (state `change.stats`); CSV is the same endpoint with `Accept: text/csv`.
